# 产品文档

> 量化交易平台（Quant Platform）产品说明。
> 面向 A 股个人量化投资者，提供行情、策略、回测、模拟交易、告警、AI 助手一站式能力。

---

## 1. 产品定位

面向 A 股市场的**个人量化交易平台**。用户可以：

- 管理自选股、查看实时行情与 K 线
- 编写 / 管理量化策略（基于 backtrader）
- 对策略进行历史回测，查看收益指标与净值曲线
- 模拟交易（Mock 券商），管理订单与持仓
- 设置价格 / 涨跌幅告警，实时接收推送
- 通过 AI 助手生成策略代码、解读回测结果、查询持仓

## 3. 功能模块

### 3.1 行情中心

- **自选股管理**：创建多个自选股列表，添加 / 移除个股
- **K 线查看**：支持 1m / 5m / 15m / 30m / 60m / 日 / 周 / 月 线
- **复权**：支持前复权（qfq）/ 不复权（none）
- **实时行情**：通过 WebSocket 推送最新价（分钟线刷新触发）

### 3.2 策略管理

- **策略 CRUD**：创建、编辑、删除策略
- **策略代码**：基于 backtrader 的 Python 代码
- **策略参数**：由策略代码或 AI 定义参数名称和说明，普通用户仅调整参数值
- **状态流转**：draft → backtested → paper_running → archived

### 3.3 回测

- **发起回测**：选择时间区间、初始资金、标的、手续费率、滑点率和策略参数
- **异步执行**：后端子进程运行，资源受限（内存 512MB / CPU 300s）
- **结果查看**：总收益、年化、最大回撤、夏普、胜率、交易次数、净值曲线
- **收益口径**：总收益率按 `期末权益 / 初始资金 - 1` 计算；默认仓位使用 95% 可用资金并按 A 股 100 股整手取整
- **历史记录**：按策略查看历史回测并恢复当次参数与完整结果
- **轮询机制**：前端轮询 run 状态直到 success / failed
- **参数分层**：回测环境参数随运行记录保存；策略参数由代码声明；接口账户、登录时段、通知和多账户分配属于实盘部署配置
- **引擎选择**：现阶段继续使用 Backtrader，以保持事件驱动策略、订单撮合和 AI 生成代码兼容；VectorBT 适合作为后续批量参数优化器，Hikyuu 暂不引入以避免形成第二套策略 API

### 3.4 模拟交易

- **券商账户**：Mock 券商（异步队列 + outbox 执行），支持多账户；新用户可在行情交易面板创建默认模拟账户
- **下单**：限价单 / 市价单，买入 / 卖出
- **撤单**：未成交订单可撤
- **持仓**：自动维护持仓与平均成本
- **A 股规则**：100 股整手、T+1、连续竞价、交易日、板块涨跌停和一字板排队；规则同时用于模拟盘和历史回测
- **订单来源**：手动 / 策略自动 / AI 触发
- **审计**：所有操作记录 audit_logs

### 3.5 告警系统

- **规则类型**：
  - 价格上穿（price_above）
  - 价格下穿（price_below）
  - 涨跌幅（pct_change，基于昨收 / 规则创建价 / 自定义基准）
  - 量异动（volume_spike，待细化）
  - 指标触发（indicator，待细化）
- **去重状态机**：Cooldown + Rearm 三态（IDLE → COOLDOWN → ARMED），防止分钟级频率下的通知轰炸
  - 冷却窗口（默认 30 分钟，可自定义 1~1440）
  - 回落重置阈值（默认 2%，可自定义 0.1~10.0）
- **通知渠道**：
  - inapp（站内实时推送，已实现）
  - email / webhook（占位，待实现）
- **触发日志**：每条规则可查看历史触发记录

### 3.6 AI 融合能力

- **能力**：
  - 在行情右侧面板按股票搜索公开事件，并缓存当日结果
  - 在策略编辑页生成、沙箱校验并应用 `BaseStrategy` 代码草稿
  - 为事件详情生成结构化影响分析与公开来源
- **安全原则**：
  - 生成类操作自动保存为草稿 / 暂停状态
  - 只读操作直接执行
  - 涉及资金的操作必须用户确认
- **交互模式**：当前非流式；AI Key 可留空启动平台，但调用 AI 能力时会返回明确配置错误

## 4. 数据来源

### 行情数据源（三级降级）

按优先级依次尝试，某个数据源失败或返回空时自动切换到下一个：

| 优先级 | 数据源 | 协议 | 优势 | 劣势 |
|--------|--------|------|------|------|
| 1 | 腾讯财经 | HTTP API | 速度快，不限流，无需额外依赖 | 无成交额字段，不支持除权除息 |
| 2 | mootdx | TDX TCP | 不限流，支持全市场股票列表 | 需连接 TDX 服务器，不支持除权除息 |
| 3 | AKShare | HTTP（东财） | 功能全，支持除权除息 | 易被限流/封禁 |

各数据源的职责分工：

| 数据类型 | 主力 | 降级链 |
|----------|------|--------|
| 日 K 线 | 腾讯 | 腾讯 → mootdx → AKShare |
| 分钟 K 线 | 腾讯 | 腾讯 → mootdx → AKShare |
| 全市场股票列表 | mootdx | mootdx → AKShare |
| 除权除息 | CNINFO | CNINFO → AKShare |

### 数据更新调度

| 数据 | 调度时间 | 范围 |
|------|----------|------|
| 日线 | 上海时间交易日 15:10 | 全市场 |
| 分钟线 1m/5m/15m | 上海时间交易日 9:30-11:30、13:00-15:00 | 自选股 ∪ 活跃告警标的 ∪ 当前在线查看标的 |
| 收盘分钟线补拉 | 上海时间交易日 15:02 | 同上 |
| 除权除息 | 首次跟踪时按需同步（成功后缓存 7 天）；每周日 16:00 全量校准 | 活跃标的 / 全市场 |

调度固定使用 `Asia/Shanghai` 和 A 股交易日历，服务器本地时区设为 UTC 也不会改变执行时刻。

### 存储

PostgreSQL + TimescaleDB（K 线 hypertable），Redis（行情缓存 + pubsub）

## 6. 后台 Worker

| Worker | 职责 |
|--------|------|
| market_worker | 定时拉取行情（日线 / 分钟线），落库 + 推送 Redis + 触发告警检查 |
| strategy_worker | 执行回测子进程（资源受限） |
| trade_executor | 消费 trade_outbox，提交订单到券商适配器 |

---

## 7. 技术约束

- 行情精度：分钟级（非 Tick 级）
- 回测：历史数据回放，非实时
- 交易：当前仅 Mock 券商，真实券商接入预留接口
- AI：非流式，有轮次限制（5 轮）和限流（10 次/分钟）
- 进程：生产运行必须同时启动 API、market_worker、strategy_worker、trade_executor 和前端
